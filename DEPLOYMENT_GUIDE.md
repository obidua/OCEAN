## 📋 What the Script Does Automatically

### **Step 1: Extract Addresses from CoreConfig**
- Reads `CORECONFIG` from `.env`
- Fetches all contract addresses using multiple getter methods:
  - `getAddress(bytes32)`
  - `getContract(string)`
  - `addressOf(bytes32)`
  - Direct function calls
- Handles duplicate names intelligently

### **Step 2: Resolve Proxy → Implementation**
- Detects proxy patterns:
  - ✅ EIP-1967 proxies
  - ✅ Beacon proxies
  - ✅ Minimal proxies
- Reads implementation from storage slots
- Falls back to direct addresses for non-proxy contracts

### **Step 3: Update .env Files**
- **Root `.env`**: Updates with new proxy addresses
  - Removes duplicate entries
  - Preserves comments
  - Creates backup (`.env.bak`)
- **Dashboard `.env`**: Auto-generates with `VITE_` prefix
  - Required for Vite to expose vars to frontend
  - All contract addresses available at build time

### **Step 4: Clean & Fetch ABIs**
- **Cleans** dashboard ABI directory (`apps/dashboard/store/Contract_ABI`)
- **Fetches** fresh ABIs from blockchain explorer
- **Validates** implementation addresses
- **Syncs** to both ABI directories (root + dashboard)

### **Step 5: Generate Reports**
- Creates detailed change reports:
  - `data/reports/abi_changes.json` (machine-readable)
  - `data/reports/abi_changes.md` (human-readable)
- Shows which addresses changed
- Tracks ABI updates

## 📦 Complete Deployment Checklist

### **Pre-Deployment**
- [ ] Deploy new proxy contracts
- [ ] Update CoreConfig with new addresses

### **Deployment Steps**

#### **1. Update Configuration**
```bash
cd /path/to/OCEAN_DeFi

# Edit root .env
nano .env
# Update: CORECONFIG=<new_coreconfig_address>
```

#### **2. Run Sync Script**
```bash
node scripts/sync_coreconfig.js
```

**Expected Output:**
```
🚀 Starting automated deployment sync...
🗑️  Cleaning ABI directory
   Deleted 27 old ABI files
📝 Creating dashboard .env file for Vite...
✅ CoreConfig sync completed successfully!
```

#### **3. Verify Changes**
```bash
# Check dashboard .env was created
cat apps/dashboard/.env

# Check ABIs were updated
ls apps/dashboard/store/Contract_ABI/

# Review change report
cat data/reports/abi_changes.md
```

#### **4. Rebuild Dashboard**
```bash
cd apps/dashboard

# Clean old build
rm -rf dist/

# Install dependencies (if needed)
npm install

# Build production bundle
npm run build
```

#### **5. Deploy to Server**
```bash
# Example: Using rsync
rsync -avz --delete dist/ user@server:/var/www/ocean-defi/

# Or: Using your preferred deployment method
# scp, ftp, docker, etc.
```

#### **6. Clear Caches**

**Server-side:**
```bash
# Nginx
sudo systemctl reload nginx

# Apache
sudo systemctl reload apache2

# Clear CDN cache (if using Cloudflare, etc.)
```

**Client-side:**
- Users must hard refresh: `Ctrl+Shift+R` (or `Cmd+Shift+R` on Mac)
- Or add cache busting to `vite.config.js` (see below)

## 🔄 Cache Busting (Recommended)

Add to `apps/dashboard/vite.config.js`:

```javascript
import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'

export default defineConfig({
  plugins: [react()],
  server: {
    port: 8786,
  },
  build: {
    rollupOptions: {
      output: {
        // Add hash to filenames for cache busting
        entryFileNames: 'assets/[name].[hash].js',
        chunkFileNames: 'assets/[name].[hash].js',
        assetFileNames: 'assets/[name].[hash].[ext]'
      }
    }
  },
  optimizeDeps: { exclude: ['lucide-react'] },
})
```

## 🛠️ Troubleshooting

### **Script Fails: "CORECONFIG missing/invalid"**
**Solution:** Ensure `CORECONFIG` is set in root `.env`

### **ABIs Not Fetching: "Explorer responded with 404"**
**Solution:** 
- Check `EXPLORER_API_URL` is correct
- Verify contract is verified on blockchain explorer
- Check if API key is required (`EXPLORER_API_KEY`)

### **Dashboard Shows Old Data After Deploy**
**Causes:**
1. ❌ Didn't rebuild: `npm run build`
2. ❌ Deployed old `dist/` folder
3. ❌ Browser cache not cleared
4. ❌ Service worker serving old files

**Solution:**
```bash
# 1. Rebuild
cd apps/dashboard && rm -rf dist/ && npm run build

# 2. Deploy fresh build
# ... your deployment ...

# 3. Clear service worker
# In browser: DevTools → Application → Service Workers → Unregister

# 4. Hard refresh
# Ctrl+Shift+R (Windows/Linux) or Cmd+Shift+R (Mac)
```

### **useUserInfoStore.js Still Has Hardcoded Addresses**
**Current Status:** The code already has `resolveAddress()` helper that checks environment variables first.

**Verify it's working:**
```javascript
// Check in browser console after build
console.log(import.meta.env.VITE_USERREGISTRY);
// Should print: "0x246c7317F4093065B96c2b0DC65A63De395444ed"
```
